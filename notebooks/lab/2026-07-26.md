# 2026-07-26 — Session 6: DGF-1 gate metric decided before the gate is written (ADR-007, proposed)

- **ADR-007 drafted, reviewed and ACCEPTED: DGF-1 Gate 1 gates on ROC-AUC *and* AUPRC, both against a floor re-run in the same batch; leaderboard positioning demoted to reported-not-gated.** Doc amendments applied on acceptance (doc-02 header/§1/§2.3/§4/§5/§6/§7/§8, doc-00 §4/§5/§7/§9, timeline DGF-1 rows). **No code** — doc-first, and not in the session it was conceived.
- **The case is registry-backed, not asserted.** Local-94 batch, 8 seeds: at *matched recall* (0.7244 vs 0.7231, Δ0.0013) GNN-local-94 precision **0.534 ± 0.140** vs RF-165 **0.913 ± 0.004** — a **0.379** gap that ROC-AUC compresses into **0.016**. That is the failure mode DGF-1's Gate 1 exists to catch.
- **It gets worse at DGraph, not better.** Labelled prevalence **1.27%** vs Elliptic's 6.5%. Synthetic Gaussian check at DGraph's exact counts (illustration, *not* a DGraph result): across the same quality range ROC-AUC moves +0.066 while AUPRC moves +0.468 — **7.1× more responsive**. A 0.03 ROC-AUC gap spans a doubling of precision.
- **Two facts made this urgent rather than tidy-up.** doc-02 §0 *already predicts a small structural delta* at degree 1.16 — small true effect + insensitive instrument is exactly how a gate passes a null. And **AUPRC is not recoverable from the registry**: rows store summary metrics, not per-node scores, so choosing later means re-running every arm — or quietly gating on what was already logged.
- **Blindness is clean, and I checked rather than assumed.** No `data/dgraph`, all 100 registry rows `model=ell1`, `adapters/dgf1/` a one-line scaffold. Blind in ADR-004's full sense; informed only by a *different* dataset. And the change only ever makes passing harder — which is also why it had to land now, not after batch #1.
- **The one clause I made softer, flagged rather than buried:** doc-02's "competitive with the published leaderboard baseline" becomes reported-not-gated, because gating it means gating on a third party's run under an unverified protocol (ADR-006 already forbids using even *our own* rows from a different code path as a gate arm). Net Gate 1 is harder — clause 2 is new and enforceable. **This is the judgment call to review first.**
- **Deliberately left open:** seed count. ADR-005 forbids assuming it — the *rule* is fixed (pilot on validation only, floor 5, ADR-006 two-stage, no open-ended top-up), the *number* goes in DGF-1's Gate-1 pre-registration ADR. ELL-1's 3-seeds-±0.031 vs 8-seeds-±0.070 is the cautionary precedent.
- **Applying the amendments found a defect in the ADR's own enumeration — and a real dependency.** The draft listed doc-02 §2.3/§4/§5/§7; three further places still specified the metric, including **§6's "Report AUC *only*"**, a flat contradiction. Recorded as a correction note in the ADR rather than silently widened. The dependency: **Gate 0's tabular floor must log AUPRC too**, because it is what clause 2 is measured *against* and it cannot be back-filled — so the "can't add it retroactively" argument bit Phase 0, not just Gate 1. doc-02 §4/§7/§8 amended.
- **Surprised:** ADR-006 had already written the escape hatch for this ("reconsidering the gate metric is legitimate, but in its own ADR, not mid-gate after seeing which metric wins") — the July-24 self-review anticipated a decision I only needed nine days later. Also: F1 was never a candidate here; ELL-1 measured the *threshold* to be the noisy part (transfer folds −0.018/+0.032, opposite signs), and both metrics I chose are threshold-free.
- **Next:** implement `auprc` in `gbe/eval/metrics.py` with its two guards. Then the phase transition (EXTRACT → DGF-1, or straight to EDR-1), which ADR-007 leaves open and unaffected either way.

## Session 7: `auprc` implemented in the core (ADR-007, code half)

- **Built:** `gbe/eval/metrics.py` returns `auprc` (`average_precision_score`, `pos_label` passed explicitly) alongside the existing four. Domain-agnostic, so `adapters/ell1/train_gnn.evaluate` picks it up for free — ELL-1 GNN rows will now carry `illicit_auprc` without touching the adapter.
- **Guards: 5 new tests, all mutation-verified.** The two ADR-007 pins (it is *not* trapezoidal `auc(recall, precision)`, gap 0.0139 on the fixture; chance level is **prevalence** ~0.05 and not 0.5 while ROC-AUC on the same uninformative scores reads 0.500) plus key-set, `pos_label`-reaches-AUPRC, and the ROC/AUPRC positive-class-agreement pin. **62 pass.**
- **Checked the guards can fail** rather than assuming — three mutations (trapezoidal form, `roc_auc_score` substituted, `pos_label` dropped) each caught by the intended guard, real implementation green. Doing this because of the July-24 lesson about a test that couldn't fail.
- **Broke exactly one existing test, correctly:** `test_gnn_strict_inductive.py` pinned the metric key set exactly, so it failed the moment a key was added — the guard doing its job. Updated to include `auprc`.
- **Found while implementing:** `adapters/ell1/baselines_tabular.evaluate` **re-states** the sklearn calls instead of calling `classification_metrics`, so it does *not* get `auprc`. Harmless for ELL-1 (closed; its dated gates are ROC-AUC/F1), but it must not be inherited — **DGF-1's floor has to route through the core function** or Gate 1's AUPRC clause has no comparator and can't be back-filled. Recorded in the `metrics.py` docstring and already binding via doc-02 §4 Phase 0.
- **Surprised:** `roc_auc_score` takes no `pos_label` and infers the positive class as the *greater* label, while `average_precision_score` takes it explicitly. They agree for 0/1 labels (every current adapter) and would silently disagree for an adapter encoding its positive class as the smaller value. Documented + pinned by a test; not "fixed", since changing ROC-AUC's call would touch ELL-1's comparability path for no present need.
- **Tomorrow's first move (researcher):** the phase transition — EXTRACT → `gbe/` then DGF-1 (doc-00 §9), or straight to EDR-1. Nothing in ADR-007 constrains that choice.
