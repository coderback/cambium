## Session 4 (cont.): Gate-1 implementation audit — the instrument, not the model

- **Audited the GNN for a defect explaining the FAIL. Found none.** Verified correct: seed/label alignment in the loss, class-weight ordering, `subgraph(relabel)` ↔ `x[test_mask]` row order, device placement, dropout train/eval. Extracted `predict_window()` from `evaluate()` so diagnostics score through the *identical* path as the gate runs.
- **Two data facts exonerate the protocol.** **Zero** edges cross the 34/35 cutoff (all 468,710 are within-time-step), so strict-inductive induction drops nothing; mean degree **2.30** (median 2), so fan-out 25 truncates 0.26% of train nodes — sampling ≈ full graph. The protocol isn't the handicap; a degree-2.3 graph whose features already encode one hop is.
- **Prevalence is severely non-stationary:** 30–32 = **20.8%** illicit, 33–34 = **6.3%**, 35–49 = **6.5%**, train overall 11.6%. The HPO sweep validated on 30–34 (16.8%) — the most positive-dense window in the dataset. That, more than the step-43 cliff, explains val F1 0.93 → test 0.68.
- **Built `scripts/diagnose_ell1_inner.py`** (train ≤29, measure 30–34, 35–49 never constructed) to price three hypothesised handicaps: model selection, threshold calibration, rank-transform.
- **All three came back below the noise floor.** Model selection +0.021/+0.029; calibration oracle ceiling +0.031/+0.077 with the two honest transfer folds at **−0.018 and +0.032** (opposite signs, 23/37 illicit); rank-transform +0.030 in one run, +0.004 in a repeat.
- **What broke — the instrument.** Same config, same seed, three repeats **in one process** on CUDA: 0.9151 / 0.9283 / 0.8939, **spread 0.0344**. CPU: identical to 8 dp, spread **0.0**. `seeding.py`'s cuDNN flags never governed PyG's scatter atomics. → **ADR-005 (proposed)**: gate-grade runs on CPU; ≥20 repeats if GPU.
- **Surprised:** my three hypotheses were all smaller than the measurement error, and the ±0.031 "seed variance" in `GATE-ELL1-1.md` is indistinguishable from the 0.034 spread of *identical* repeats — that column is largely run noise. Gate-1 verdict unaffected (0.127 deficit ≈ 4× the floor); its stated precision is not.
- **Tomorrow's first move:** decide ADR-005. If accepted, time one full 40-epoch CPU run on 1–34 (unmeasured — the 5-epoch probe does not extrapolate), then harden `gbe/run/seeding.py`. Handicaps stay closed as *unmeasurable*, not refuted, until the instrument is fixed.

## Session 4 (cont.): Phase-3 edge-scramble + the instrument, fixed

- **Edge-scramble answers Gate-1's open question: the GNN *is* using the graph.** 6 seeds/arm, steps 35–49, GPU, provisional (`dirty=true`): real **F1 0.6763 ± 0.0790 / AUC 0.9191 ± 0.0140**, scrambled **0.5597 ± 0.0288 / 0.8818 ± 0.0068**. Drop **+0.117 F1** (SE 0.038, p=0.020) and **+0.037 AUC** (SE 0.007, **p=0.0009**). AUC is the decisive read — threshold-free, so it dodges the calibration noise that dominates F1. The "model is reading features, not structure" branch of doc §4 does **not** fire.
- **This reframes the Gate-1 lesson.** Scrambled GNN **0.560** < real GNN **0.676** ≪ RF **0.806**. Message passing is worth a real +0.117, but the *neural* feature path sits ~0.25 below what a tree extracts from the same 165 features. The failure was never "structure doesn't help on Elliptic" — it's that the structural gain doesn't cover a neural-vs-tree deficit on tabular features. Better sentence for P0 than the gate file currently supports, and it retires the trees-vs-neural / graph-vs-no-graph confound.
- **Built:** `gbe/eval/ablations.py::scramble_edges` — permutes node identity **within each time step**; a global permutation would forge edges spanning the 34/35 cutoff, which either leaks the future or gets silently dropped by induction, in both cases voiding comparability. Preserves degree sequence, per-step edge count, symmetry, split. + `scripts/run_ell1_edge_scramble.py` (re-runs its own real arm — never reuse Gate-1 rows across a code path). Tests: **49 pass**.
- **What broke, then got fixed — the instrument.** CUDA nondeterminism traced to scatter-reduce atomics (float addition isn't associative; ~1e-7 divergence × 1200 steps). `cudnn.deterministic` was inert all along — it governs conv/RNN algorithm choice, which a GNN has none of. `torch.use_deterministic_algorithms(True)` + `CUBLAS_WORKSPACE_CONFIG=:4096:8` → **bit-for-bit, ~5% cost**. Verified at full gate length: 40 epochs on 1–34, seed 0, twice = `0.56554307`.
- **I was wrong in the first ADR-005 draft** (CPU-for-gates, ~12.4 min/run) — I assumed PyG's scatter had no deterministic CUDA kernel instead of spending two minutes testing it. Deterministic CUDA is 1.3 min/run: same guarantee, 9.5× faster. ADR-005 rewritten + renamed, wrong turn kept as a revision note; `seeding.py` hardened (env var at **import**, not in `seed_everything` — setting it later is a silent no-op) with 5 new guards.
- **ADR-006 drafted** pre-registering Gate 3: resolvability test `drop > 2×SE_diff` for edge-scramble / random-graph / GNN-removed; F1 stays primary (switching to AUC *after* seeing it win would be forking-paths); doc §7's "drops to ~baseline" amended — the scrambled GNN lands *below* the RF floor, so convergence-on-baseline is unsatisfiable. Carries an explicit disclosure that clause 1 is **informed, not blind**; clauses 2–3 are genuinely blind.
- **Surprised:** three plausible values for "GraphSAGE at seed 0" — 0.6390 (Gate-1), 0.5345 (scramble batch), 0.5655 (deterministic). And 6 seeds give ±0.079 where 3 gave ±0.031, so Gate-1 under-sampled a genuinely wide distribution on top of the run noise.
- **Tomorrow's first move:** accept/reject ADR-005 + ADR-006 (Gate-3 must not run before ADR-006 is accepted, or clauses 2–3 lose their blindness). Then build the random-graph and GNN-removed arms and run the authoritative 4-arm × 8-seed deterministic batch (~42 min).
