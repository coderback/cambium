## Session 15: the feature transform — `Standardizer` extracted to the core; DGF-1 inputs fitted on train

- **Profiled first, on training-window users only** (label-free).
  - **−1 is a clean sentinel:** in all 17 columns the non-sentinel minimum is ≥ 0, and nothing lies in (−1, 0). So ELL-1's affine standardisation keeps "missing" separable by a single threshold: no indicator columns, and no new modelling decision.
  - Missingness comes in blocks: 38.6% of users miss 14 columns, 10.4% miss 16.
- **Found a defect the inherited formula would have shipped silently.**
  - `edge_type_8` is **zero for every training user**. All **84,338** type-8 edges are dated **529–821, inside the test window** only: none in train, none in val.
  - ELL-1's `std.clamp_min(1e-6)` would have fed test users type-8 counts × ~1e6. Measured: max |z| over test targets **5×10⁶ under the inherited clamp vs 483 with the fix**, and **16,229 test targets** carry a type-8 edge.
  - Neither the retune nor the pilot would ever have hit it, since val has no type-8 edges. It would have surfaced only at gate scoring, if at all.
- **Built:**
  - `gbe/features/scaling.py`: a `Standardizer` with frozen statistics fitted on the fit rows only. A column with **exactly zero** training variance maps to 0 everywhere. This is **extracted from ELL-1**, which now delegates to it: DGF-1 is the second identical use (doc-00 §1).
  - `adapters/dgf1/features.py`: inputs = the raw 17 + 13 view features (30 columns). They are fitted on users with `node_time ≤ 369` **from the training view** and frozen for every scoring view. The tree floor takes the inputs untransformed.
- **ELL-1 unchanged, checked:** its standardised features are `torch.equal` to the pre-extraction formula on real Elliptic at 34 and 29, and the zero-variance rule is inert there (smallest training std 0.237 / 0.160). **This touches an ELL-1 path, so the ADR-008 check needs a re-run after this commit.**
- **Tests: 125 → 139.** Clause-5 **test 7 is done.** A mutation check broke four behaviours and all four were caught: fitting on all users (2 tests failed), fitting on the end view (3), removing the zero-variance rule (3), refitting at transform time (6). One failure was my fixture's fault: a 1e-9 ramp on 3.0 rounds to a constant in float32, so I moved the ramp near 0.
- **For the Gate-1 ADR:** type 8 is a relation that **only exists in the test window**, which is a distribution shift in the edge types. The homogeneous GNN still passes messages over those edges (clause 4 allows it), but its histogram column reads 0 for both arms. That should be stated, not discovered at write-up.
- **Next:** commit, then `check_extract_regression.py --run`. After that, the parity floor (clause-5 test 8), then the temporal-sampler determinism test (test 10).

- **Determinism, on synthetic data:** hist on CPU, multithreaded, gives **bit-identical predictions at the same seed**. **But without subsampling, different seeds also give identical predictions: the seed is inert.** A default-settings XGBoost floor therefore has zero seed variance, like ELL-1's LR (±0.0000). That is not wrong, but it means Gate-1's resolvability test would take all of `SE_diff` from the GNN arm. **Whether the floor subsamples, and so has real seed variance, is a Gate-1 pre-registration decision**, alongside its hyperparameters at ~860k rows.

## Session 18: the temporal sampler passes; the first-appearance row may be produced

- **Built:** `adapters/dgf1/sampling.py`.
  - `first_appearance_loader`: PyG `NeighborLoader` with `time_attr="edge_time"` and `input_time = node_time`, so each scored user sees only edges dated at or before its own node time, **at every hop**.
  - `assert_temporal_batch`: a per-batch guard, cheap enough to run at scoring time, not just in tests.
  - `batch_signature`: for exact run-to-run comparison.
  - Checked PyG's source first: edge attributes are sliced with the same permutation as `edge_index`, `batch.batch` maps nodes to seeds (temporal sampling forces disjoint subgraphs), and `batch.seed_time` carries the seeds' times.
- **Clause-5 test 10 done**, on the fixture:
  - the constraint holds in exact and fan-out modes;
  - **negative control:** a non-temporal loader on the same view does sample later edges, and the guard rejects them;
  - identical batches at the same seed under strict determinism;
  - exact mode has no randomness at all;
  - **second control:** a truncating fan-out responds to the seed.

  Tests 153 → 160. Mutation check: dropping the constraint (2 tests failed), a no-op guard (1), and a **+100-step look-ahead** (1) were all caught. The per-batch guard alone *passes* the look-ahead, because it trusts `seed_time`; only the seed-time == node-time test catches it. That is why both exist.
- **Real graph, `scripts/verify_dgf1_temporal_sampler.py`, validation window only** (targets 370–481, 5,408,862 eligible edges as of 481; no model, no scores, no label values, no row):
  - **exact** [-1,-1,-1]: 180 batches, 1,604,252 sampled edges, **every batch within its seed's time, two seed-0 passes identical**;
  - **fan-out** [25,10,10]: 1,406,735 edges, same, and **seed 1 differs**, so the seed is live.
  - About 1 s per pass.
  - **PASS: the first-appearance row may be produced** (ADR-011 clause 4).
- **Which mode that row uses is still open.** It follows how the gated view is scored, which the GNN-trainer session decides.
- **Next:** draft the **Gate-1 pre-registration ADR**. EXTRACT's DataSource, transform, floor and sampler are all in place, and all ten clause-5 tests are done. The ADR has five open items: the recency features, the young val window, test-window-only edge type 8, floor hyperparameters at scale, and floor subsampling / seed variance.
